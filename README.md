# СдамППА (sdamppa)

Интерактивная платформа подготовки к экзаменам: **вложенный граф подсказок** (в духе Crusader Kings / Paradox), **геймификация**, **код/прод-применимость** и день-за-днём учебный план. Первый предмет — «Статистика и анализ данных» (под допсессию). Архитектура **мульти-предметная**: новый предмет (например, матан) добавляется как модуль контента, без правок движка.

Стек: **Svelte 5 + SvelteKit** (`adapter-static`, чистая статика) · **Tailwind v4** · **KaTeX**. Хостинг — любой статический веб-сервер.

## Команды

```sh
npm install        # зависимости
npm run dev        # дев-сервер (HMR)
npm run build      # статический билд → ./build
npm run preview    # локальный предпросмотр билда
npm run check      # svelte-check (типы + a11y)
```

## Деплой на свой сервер

Билд — это статика в `build/`. Заливаем и отдаём любым веб-сервером со **SPA-fallback** (чтобы прямые ссылки `/statistics/day/5` открывались).

```sh
SERVER=user@host REMOTE=/var/www/codex ./deploy/deploy.sh
```

Конфиги веб-сервера: [`deploy/nginx.conf`](deploy/nginx.conf), [`deploy/Caddyfile`](deploy/Caddyfile). Если приложение живёт не в корне домена, а в подпути (`/codex`), добавь в `vite.config.ts` в опции `sveltekit({ ... })` поле `kit.paths.base` и пересобери.

## Архитектура (предметно-независимое ядро)

```
src/lib/
  types.ts              # КОНТРАКТ контента: Subject / Day / GlossaryTerm / Task ...
  markup.ts             # парсер «codex-разметки» (мини-markdown + математика + термины)
  engine/               # движок — НЕ знает о конкретных предметах
    tooltips.svelte.ts  #   менеджер подсказок (hover-пик, hold-пин, граф закреплённых карточек)
    Term.svelte         #   инлайн-термин (наведение/таймер-кольцо/пин)
    HoverPopover.svelte #   всплывающий пик
    PinCard.svelte      #   закреплённая перетаскиваемая карточка (с вложенными терминами)
    RichText.svelte     #   рекурсивный рендер разметки → текст/математика/термины
    Katex.svelte        #   рендер формул
  stores/progress.svelte.ts   # геймификация: XP, стрики, ранги, прогресс (localStorage, на каждый предмет)
  components/           # Calendar, DayView, TaskCard, CodeBlock, XPBar
  content/
    index.ts            # РЕЕСТР предметов  ← единственное место, куда добавляется предмет
    statistics/         # предмет: phases.ts, glossary.ts, days/, index.ts
    matan/              # предмет-заглушка (доказательство расширяемости)
src/routes/
  +page.svelte               # витрина предметов
  [subject]/+page.svelte     # дашборд предмета (календарь + XP)
  [subject]/day/[n]/         # просмотр дня
```

## Как добавить предмет (например, матан)

1. Скопируй `src/lib/content/matan/` как образец (он уже по контракту `Subject`).
2. Заполни `phases`, `glossary` (граф терминов) и `days` (по образцу `statistics/days/day01.ts`).
3. Зарегистрируй в `src/lib/content/index.ts`:
   ```ts
   import { matan } from './matan';
   export const subjects = [statistics, matan];
   ```

Больше **ничего** менять не нужно: движок, геймификация, маршруты и подсказки работают с любым предметом, удовлетворяющим контракту.

## Codex-разметка (как писать контент)

Любое поле `body`/`prompt`/`solution`/`goal` — строка в мини-markdown. **Пиши в `String.raw\`...\``**, чтобы бэкслеши LaTeX не съедались.

```
**жирный**   *курсив*   `код`
$inline математика$        $$выносная математика$$
[[term-id]]                ← подсказка по канону термина
[[term-id|видимый текст]]  ← подсказка с произвольной подписью (можно с $математикой$)
- маркированный список     1. нумерованный список
## заголовок               (пустая строка разделяет абзацы)
```

Термины в `[[...]]` ссылаются на `id` из `glossary`. Внутри определения термина можно ссылаться на другие термины — так получается **вложенный граф подсказок**. Несуществующий `id` отрисуется серым (не сломается).
